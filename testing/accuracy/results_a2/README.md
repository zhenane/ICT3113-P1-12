# Assignment 2 Accuracy Results

The results currently recorded here were collected on a laptop using Docker.
The test set was `golden-test-set/final/even_test_set.csv` (105 tickets). The
cascades ran with `llama3.2:3b` as the small model and `qwen3:1.7b` as the large
model. The service used its 60-second Ollama timeout. Failed service requests
were counted as wrong; no retries were performed. Update these results with
the Ryzen run when it is available.

Single-model results below reuse the saved A1 per-ticket predictions, scored on
the even test set. Reuse for final results depends on matching the assignment's
model, prompt, Ollama version, and hardware conditions.

## A2 relative-limit outcomes

| Configuration | Correct / 105 | A2 overall | A2 category limits | Outcome |
|---|---:|---|---|---|
| `qwen3:1.7b` | 58 | Pass (minimum 48) | Pass all seven | Pass |
| `llama3.2:3b` | 35 | Fail | Fails Credit reporting, Debt collection, Money transfer or service | Fail |
| `llama3.2:1b` | 18 | Fail | Fails multiple categories | Fail |
| `qwen3:4b` | 0 | Fail | Fails all seven | Fail |
| S1 (`L=0`) | 56 | Pass (minimum 48) | Pass all seven | Pass |
| S2 (`L=80`) | 47 | Fail (one below 48) | Fails Credit reporting, Debt collection, Consumer loan | Fail |

The cascade A2 checks were run with `compute_limits.py --check`. The
`accuracy_report.md` files generated by `run_accuracy.py` also show A1
requirements; those A1 pass/fail rows are not the A2 relative-limit verdict.

## Cascade details

| Setting | Failed requests | Escalated | Escalated accuracy | Non-escalated accuracy |
|---|---:|---:|---:|---:|
| S1 (`L=0`) | 16: 14 timeouts, 2 Ollama HTTP 500s | 96/105 (91.4%) | 47/96 (49.0%) | 9/9 (100%) |
| S2 (`L=80`) | 31: 30 timeouts, 1 Ollama HTTP 500 | 81/105 (77.1%) | 33/81 (40.7%) | 14/24 (58.3%) |

Against the committed forecasts, S1 scored 56/105 versus 57/105 predicted and
passed all A2 limits. S2 scored 47/105 versus 54/105 predicted; its overall
accuracy was seven tickets below forecast, and it failed the overall limit and
three category limits. The service errors, which count as wrong, likely
contributed to the S2 miss; compare with the Ryzen run when available.
